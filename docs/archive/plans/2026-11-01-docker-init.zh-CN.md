历史实施计划。文中验收状态以当时阶段为准；当前部署状态见 [部署记录](../live-deployment.zh-CN.md)。

目标：以 Go 实现独立的容器初始化流程，保留原生系统服务安装。容器只使用 OpenAI 隧道作为 MCP 入口。

- [x] 增加 `init --container`、导入/重复初始化/重新向导，原子发布持久化配置。
- [x] 提供独立 `compose.init.yaml`；正式 Compose 只读挂载配置，以重启策略管理服务。
- [x] 覆盖向导、凭据落盘、权限、失败保持旧配置、CLI 参数隔离及原生回归。
- [x] 构建镜像，通过实际初始化容器和正式 Compose 完成 OpenSSH、PTY、SFTP 验证。
- [x] 更新 README 和验证记录。

配置目录默认为宿主机 `data/`，在初始化和运行容器中均挂载为 `/etc/tunnel-ssh`。每次生成独立的 `generations/init-*`，校验成功后原子切换相对符号链接 `current`。凭据引用指向具体代次，避免运行中的进程混用新旧凭据。正式进程 UID/GID 为 1000，配置和凭据权限为 0600。

首次向导默认使用自带 `dev` 环境，其 SSH 私钥由开发容器首次启动时生成。外部 SSH 可使用密码或通过 `/input` 导入私钥。初始化不连接 OpenAI、不安装系统服务、不启动正式容器。真实隧道接入需用户自己的运行时凭据另行验收。
